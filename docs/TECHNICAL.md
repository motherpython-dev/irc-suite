## 2. Процессы

| Процесс | Запуск | Что делает |
|---|---|---|
| **Главный** `iRC.exe` | ярлык | ядро, сервер, клиент сима, модули, трей, Tk-хост (оверлей рейс-контроля) |
| **Панель** `--panel <url>` | при старте или из трея | окно WebView2 с `/` |
| **Пульт** `--deck <url>` | переключатель / трей | окно WebView2 с `/deck`, поверх всех окон |
| **Оверлеи** `--overlays <url>` | при первом выводе оверлея в эфир | все окна оверлеев |
| **RUTP** | модуль rutp | внешний агент |

- Второй запуск ярлыка не поднимает второй сервер: порт-семафор `127.0.0.1:8778`,
  второй экземпляр просит первый показать панель (`POST /api/panel`).
- Дочерние окна привязаны к job-объекту (`_die_together`) и гасятся деревом
  процессов при выходе (`taskkill /T`).
- Главный поток занят Tk, поэтому окна WebView2 живут в отдельных процессах.

## 3. Ядро и бандл

Программа делится на **ядро** (exe: интерпретатор, зависимости, `bootstrap/`)
и **бандл** (`app/suite/`: вся логика и веб-страницы).

- `bootstrap/version.py` — `CORE_VERSION`. Поднимается, когда меняется
  `bootstrap/` или зависимости в `build/irc.spec`.
- `app/suite/core/version.py` — `VERSION` бандла. Пишется `build/make_bundle.py`.
- Бандлы разворачиваются в `%LOCALAPPDATA%\iRC\versions\<версия>`, активная
  указана в `current.json` (`current`, `last_good`, `fails`).
- При старте: откат на `last_good`, если `fails ≥ 2`; разворачивание seed-бандла
  из exe, если он новее активного; `note_start` → после подъёма `note_ok`.

**Важно для разработки.** Бандл грузится динамически, PyInstaller его импортов
не видит: всё, что импортирует бандл из сторонних пакетов и stdlib, должно быть
в `hiddenimports` в `build/irc.spec`. Сам бандл туда добавлять нельзя —
frozen-импортёр перекроет обновлённую версию.

## 5. Модули

Модуль — объект с контрактом (`core/modules.py`):

```python
class Module(Protocol):
    id: str
    title: str
    def start(self, ctx: Context) -> None: ...
    def stop(self) -> None: ...
    def status(self) -> dict: ...     # попадает в /api/state → modules[]
    def routes(self) -> dict: ...     # {"GET /api/<id>/...": handler}
```

`Context`: `sim`, `rc` (команды в сим), `storage`, `publish` (SSE), `config`
(свой раздел), `save_config`, `log`, `app`.

- Все модули в одном процессе и делят один `SimClient`: несколько читателей
  shared memory дали бы кратный опрос и дублирование переподключения.
- Маршруты модуля доступны, только пока модуль запущен.
- Включение и выключение на лету: `POST /api/modules/set`. Запуск модулей
  разрешён только при допуске (раздел 10).

Регистрация — в `bootstrap/main.py` (`app.register(...)`), то есть новый модуль
требует нового exe.

## 6. Клиент сима

**Живой кадр для подсчётов поля** — `SimClient.live_frame()`: режим LIVE по
ленте повтора или, запасной признак, своя машина на трассе (`IsOnTrack`) и
не идёт повтор (`IsReplayPlaying`). В онлайн-практике после сброса сессии
лента залипает на «повтор» — без запасного признака отрывы, питы, сектора,
флаги и лучший круг вне гонки не считались. Эфир и оверлеи пилота сбрасывают
всё накопленное и при смене `SessionNum` (практика → квалификация → гонка в
одной подсессии). Демо проверяется по типам сессии:
`POST /api/demo {"on": true, "session": "practice" | "qualify" | "testing" | "race"}`.

`core/simclient.py` — единственный читатель irSDK.

- Режимы: `LIVE`, `REPLAY` (по `ReplayFrameNumEnd`), `OFFLINE`.
- Снимок `Snapshot`: сессия, время (в REPLAY — оценка живого), игрок, пилоты
  (`Driver`: `car_idx`, `car_number`, `name`, `user_id` = номер аккаунта
  iRacing, команда, класс), трасса, флаги.
- Переподключение к залипшему буферу (клиент, поднятый до сима).
- Камеры: группы из `CameraInfo`, состояние `CamCarIdx/CamGroupNumber`,
  переключение `cam_switch_num(номер, группа, 0)` — группа всегда явно.
- **Демо** (`set_demo(on, race)`): источник гонки вместо сима. Своё у модулей
  трансляции и пилота: `replay_demo.ModuleDemo` держит отдельный `SimClient`
  в режиме демо, модуль читает его через свойство `sim` (иначе — общий
  `ctx.sim`). Общий сим и рейс-контроль демо не видят. Источники:
  - `replay_demo.ReplayRace` — прошлая гонка из `core/demo_race.json`
    (едет в бандле, одна на всех; снята с сайта `/api/desktop/race_replay`,
    поле `me` — cust_id «своей» машины для пилота). Положение — интерполяция между
    пересечениями линии; круг с питом — темп до 0.94 круга, затем бокс.
    Отрыв — время, когда лидер был на той же дистанции. По кругу, 1:1;
    номер прохода — `session_num`, номер гонки — `subsession_id`, чтобы
    модули сбрасывали накопленное. Своя машина — `demo_me()`;
  - `demo.DemoRace` — синтетика, запасной вариант: время ×8, старт с 9
    круга, состав из `demo-roster.json`.
  Цвета ливрей — `core/livery_colors.py`: `<paint>/<CarPath>/car_<UserID>.tga`
  (`car_team_<TeamID>.tga`), фон шаблона по краю текстуры, без чёрного/белого/
  серого, второй цвет — не ближе 60° по оттенку; фоновый поток, кэш по пути и
  mtime. В строке поля — `liv`, в ячейках — `color` / `color2`.
  Радар в демо пилота — `core/radar_script.py` (сценарий мокапа, тот же у
  «Индикатор всегда»): поперечного положения в прошлой гонке нет.

Подтверждено на живых сессиях и не подтверждено — SPEC.md, раздел 8.

## 7. Трансляция

### 7.1. Данные

`modules/broadcast/__init__.py` раз в `1/refresh_hz` собирает строки поля и
отдаёт источники оверлеев: `/api/broadcast/tower|grid|commentators|delta|pits`.
В ответе каждого — `visible`: в эфире ли оверлей. Видимостью управляет iRC
(`visible` в конфиге), а не сцены OBS.

- **Пит-стопы** — `PitTracker`: остановка по въезду в бокс.
- **Сектора** — `sectors.py`: границы из `SplitTimeInfo.Sectors[].SectorStartPct`,
  положение `CarIdxLapDistPct`, момент пересечения интерполируется между
  замерами. Только LIVE.
- **Места** — `RaceOrder`: `CarIdxPosition` обновляется на линии, поэтому пока идёт
  гонка (`SessionState` 4) порядок — по пути (`GapClock.pos`, в повторе — по кадру,
  без истории), с допуском 0,0005 круга против дрожания; до старта и после финиша —
  официальный. Накопленное сбрасывается при смене сессии только в живом режиме.
- **Инки на пульте** — прибавка `driver_incidents()` в живом режиме: `inc_new`,
  `inc_fade` в карточках, `INC_FLASH_S`.
- **Отрывы** — `GapClock`: по каждой машине история пути (круг + `CarIdxLapDistPct`)
  во времени, отрыв = сейчас − момент, когда машина впереди была в этой точке
  (интерполяция). `CarIdxF2Time` сим обновляет только на отсечках — он остаётся
  запасным, пока истории нет. Отрыв считается на момент замера положения машины, а не на
  момент запроса (иначе дрожал на десятые). Только гонка и LIVE; сброс при смене сессии
  (`SessionNum`). Разрыв пары и режим «до впереди» — оттуда же.
- **Практика / квалификация** — `timing()` отдаёт всех пилотов, кроме
  зрителей (`IsSpectator`), даже с `CarIdxPosition` = 0; башня (`_qual_order`)
  ставит по `best_lap`, отрыв — от лучшего, у строк поле `qual` (формат `gap3`
  показывает время лидера). Решётка без результатов квалификации — тот же порядок.
- **Погода** — `SimClient.weather()`: `AirTemp`, `TrackTempCrew`, `WindVel`,
  `WindDir` (откуда дует, рад), `RelativeHumidity`, `Skies`, `SessionTimeOfDay`;
  чего нет в телеметрии — из `WeekendInfo`. SOF — по `DriverInfo.IRating`.
- **События** — лента модуля: инциденты рейс-контроля текущей сессии (1x вне
  трассы, 2x потеря контроля, 4x контакт; при запуске посреди гонки старше
  40 с не берутся) и смены флага (`FlagWatch`). В демо — по прибавке
  `driver_incidents()`.
- **Лучший круг** — минимум `best_lap` по полю; первый взгляд запоминается без
  плашки, новый рекорд показывается `BESTLAP_SHOW_S` = 8 с.
- **Очки решётки** — `POST /api/desktop/standings {stage_plan_id | subsession_id}`
  на сайте (таблица `ChampionshipStanding`), раз в 2 минуты; сверка по
  `cust_id` (`DriverInfo.UserID`). Колонка — со второго этапа.

### 7.2. Описания оверлеев

Оверлей — JSON (`modules/broadcast/specs.py`, `DEFAULTS`):

```
style (версия оформления, STYLE = 2)
width, enter (left|right|up|down|fade)
frame {radius, shadow, flag_stripe, wave,
       surface {fill, glow, border, edge}}      — панель, свечение из угла, рамка, кромка
palette {...}, fonts {num, text, ui}, font_faces [{family, src}]
header / footer  {height, bg {fill, shape}, elements[]}
flagbar {height, margin, radius}                — плашка флага под шапкой (data.flag_bar)
body  type: list | grid (columns, page_size, page_seconds) | cards (+ tail) | single
      pad — отступ сверху и снизу
      sep {after: "$.sep_after", height, text}  — разделитель «топ + окно» (list)
      item {width, height, bg {fill, alt, shape}, states {leader, in_pit…}, elements[]}
```

Состояния строки: `leader in_pit focus closing growing gained lost fastest`;
шапки и подвала — `yellow green` (по `flag_tone`). `fill: "@поле"` — цвет из
данных строки (`@color` — ливрея из `CarDesignStr`).

Флаги (`FlagWatch`): смена `SessionFlags` -> `flag_event {id, tone, age}`;
оверлей с `frame.wave` прогоняет одну волну сверху вниз (1,1 с, вспышка строки
0,55 с), если событие свежее 1,5 с. `flag_tone` красит кромку и заголовок,
`flag_bar` — плашка («пейс-кар на трассе», 5 с после зелёного — рестарт/старт).

Башня «топ + окно»: `tower_top` (10) + `tower_window` (8) строк; окно вокруг
`focus_car` или машины в кадре (`CamCarIdx`), в ответе `sep_after win_from
win_to win_note`.

Элемент: `type` (text | chip | box | image), `x y w h`, `text` — шаблон
`{поле|формат}` или `{$.поле_корня}`, `when` (`leader`, `!in_pit`, `$.pages>1`),
`states` — переопределения цвета и заливки; `fill: "class"` — цвет класса;
у картинки `fill_h` + `pad` + `aspect` — высота по разделу.

Форматы: `surname upper gap gap3 make fixed1 fixed3 plus3 laptime sec1 slash trend source_label`.

Правки пользователя — `%LOCALAPPDATA%\iRC\overlays\<id>.json` поверх умолчаний
(списки заменяются целиком). Файлы без `style` = текущему `STYLE` не
накладываются (и не удаляются): в них целиком лежит прежнее оформление. `version` = время изменения файла: по нему
открытые оверлеи перестраиваются. Загруженные файлы — `overlay-assets\`
(до 10 МБ).

### 7.3. Два отрисовщика одного описания

| | `web/ov/render.js` | `core/ui/ov_paint.py` |
|---|---|---|
| Где | OBS (`/ov/<id>`), предпросмотр редактора | окна поверх iRacing |
| Как | DOM, CSS-анимации | PIL → RGBA → слоистое окно |

**Меняешь смысл описания в одном — сверяй с другим.** `ov_paint` повторяет
вёрстку `overlay.html` (выравнивание текста по центру строки, многоточие,
скосы `SLANT = 0.22`, тень `0 8px 22px -8px`, поле 14 px), строки рисует
плитками с кэшем и плавным переездом при обгоне.

Шрифты в `ov_paint`: реестр Windows и шрифты бандла (`assets/fonts`,
`web/ui/fonts` — Exo 2 и Roboto Mono, вариативные: толщина ставится осью);
загруженные — с сервера; курсив и жирный, которых нет у шрифта, — искусственные.
Подстановки шрифта по глифу нет: значки вроде ▲▼ — элементом со своим шрифтом
(Segoe UI Symbol).

### 7.4. Окна оверлеев (`core/ui/overlay_host.py`)

Процесс `--overlays`: окно Win32 на каждый оверлей, картинка выводится
`UpdateLayeredWindow` с попиксельной альфой (BGRA, предумноженная).

- Стили: `WS_EX_LAYERED | TOOLWINDOW | TOPMOST | NOACTIVATE`, `MA_NOACTIVATE`;
  показ `SW_SHOWNA` — фокус у iRacing не забирается.
- Перетаскивание: `WM_NCHITTEST → HTCAPTION`; по `WM_EXITSIZEMOVE` место уходит
  в `POST /api/broadcast/position`. Координаты — физические пиксели.
- DPI: процесс per-monitor aware, картинка в масштабе монитора.
- Поток на оверлей: описание раз в 2 с, данные раз в 0,4 с, кадр только при
  изменении или во время движения строк (30 к/с).
- Появление: сдвиг 26 px за 0,26 с и проявление за 0,22 с, уход — обратно,
  затем `SW_HIDE` (спрятанное окно не ловит мышь).
- Сервер молчит 20 с — процесс завершается.

**Почему не WebView2:** окно WebView2 не бывает прозрачным до рабочего стола.
Проверено пиксельным замером: флаг `transparent`, цвет-ключ `LWA_COLORKEY` и
«стекло» DWM — во всех вариантах под оверлеем оставалась подложка.

### 7.5. Пульт и макросы

Пульт рисует `web/ui/deck.js` в трёх местах: вкладка «Пульт» главного окна,
`web/deck.html` в окне `--deck` поверх сима и `/deck` с телефона. Данные
пульт опрашивает сам, пока он на экране: карточки раз в 0,6 с, эфир и камеры
раз в 1,5 с, макросы раз в 2,5 с.

- Таблица пилотов — строки с `data-key` по номеру машины: `setHTML` меняет
  текст и переставляет строки, не пересоздавая их; поиск, клик →
  `POST /api/broadcast/camera`. Уже 700 px — без секторов и кругов.
- Клавиши: F1–F5 — оверлеи, Esc — убрать всё, 1–9 — группы камер, «/» — поиск.
- Макросы (`macros.py`): `normalize_macros` проверяет шаги,
  `MacroRunner` выполняет в потоке с отменой.

```json
{"id": "cockpit-delta", "title": "Кокпит + разрыв", "steps": [
  {"type": "camera", "group": "Cockpit", "car": "focus"},
  {"type": "wait", "sec": 1.0},
  {"type": "overlay", "id": "delta", "action": "show"}]}
```

`car`: `focus | leader | <номер>`; `action`: `show | hide | toggle | only`;
`id: "*"` — все оверлеи.

### Режиссёр (`modules/broadcast/director.py`)

- **Инциденты** — свои, по росту `CurDriverIncidentCount` (как подсветка строк пульта), только в LIVE:
  `{id, car_number, name, delta, lap, session_num, session_time}`, до 30 за сессию. Рейс-контроль не нужен.
- **Повтор** — `POST /api/broadcast/replay {id}`: шторка `in` (0,5 с) → `replay_search_session_time`
  дважды (время − `pre_roll`, 6 с), камера на машину в текущей группе, скорость 1 → `cover`, пока сим
  не встал (`_settle`: `ReplayFrameNum` отскочил от прежнего и дважды подряд растёт ~60 к/с; в LIVE —
  `ReplayFrameNumEnd` ≤ 10; не меньше 0,6 с, не больше 4 с; в журнал — сколько держали) →
  `out` 0,5 с. `{live: true}` — `replay_search(to_end)` той же шторкой. Фаза шторки — `GET /api/broadcast/fx`.
- **Камера на инцидент** — `director.inc_cam`, порог `inc_min` (1/2/4x); автосмена после этого ждёт 8 с.
- **Автосмена камер** — `auto_cam`, `auto_groups` (имена групп), `auto_every` (с): следующая группа,
  машина та же. Настройки и журнал — `GET/POST /api/broadcast/director`.
- **Шторка повтора** — вариант `replay_fx` (A шеврон, B ламели, C диафрагма, D скос), тайминги
  `FX_TIMES` (закрыть / открыть) одни в `director.py`, `core/ui/fx_paint.py` и `web/ov_replay.html`.
  `GET /api/broadcast/fx`: `{phase, t, dur, n, variant, word, bug}`. Окна поверх сима: `FxFeed` в
  `overlay_host` — `replayfx`: шторка из окон-деталей (`FxStage`/`Sprite`, картинки — `FxSprites` в
  `fx_paint`): панели, пластины, линии свечения, логотип — каждое своё слоистое окно с готовой
  картинкой, кадр — только сдвиг и прозрачность окон по таймеру окон (10 мс, шаг 0,2–1 мс);
  диафрагма — вырез окна по кругу (`SetWindowRgn`). Перерисовка всего экрана на кадр (3440×1440 —
  25–30 мс) рвала анимацию. Детали готовятся заранее при смене варианта; клики насквозь.
  `replaybug` — метка, перетаскивается. Для OBS —
  `/ov/replayfx` и `/ov/replaybug` (CSS-анимации мокапа). Метка: `replay_bug`, «● LIVE» 3 с после возврата.
- **Башня в повторе** — по кадру повтора; если у большинства машин нет положения (сим ищет кадр),
  держится последняя целая картина. Раз в 15 с в журнал — сводка кадра повтора (строк, с положением, с местом).

## 8. Рейс-контроль

`modules/racecontrol/`:

- **Детектор** (`detector.py`): инциденты по счётчикам и выездам за трассу
  (`offtrack_enabled`, `min_offtrack_seconds`, `offtrack_cooldown`), склейка в
  окне `merge_window`. В REPLAY продолжает считать, пропущенное сбрасывается
  при возврате в LIVE.
- **Показ инцидента:** перемотка `replay_search_session_time` (нужно два
  вызова) с запасом `pre_roll_live` 10 с / `pre_roll_estimated` 20 с, камера
  `incident_camera`. После перемотки данные поля обнуляются ~10 с.
- **Флаги** (`flags.py`): админ-команды в чат из `chat_commands` —
  `yellow, pace_laps, clear, clear_all, drive_through, time_penalty, dq, wave_by, eol`.
  Синтаксис не подтверждён на живой сессии, поэтому вынесен в конфиг. В
  интерфейсе отдельно остались только жёлтый и «снять все ЧФ»; наказания
  выдаются из карточки инцидента.
- **Решение по инциденту** (`RaceControlModule.decide`, `POST /api/racecontrol/decide`):
  `racing` — гоночный; `penalty` — наказание (`drive_through | time_penalty | eol | dq`,
  машина — виновник или сосед) сразу уходит командой в чат; `review` — изучить
  после гонки. Хранится в `incidents.decision / decision_detail / synced`
  (миграция `incident_decision`). Выданное наказание не меняется.
- **Лайв-судейство** (`live.py`, `LiveLink`): по номеру сессии, `TrackID` и
  `LeagueID` из `WeekendInfo` сайт находит этап (`POST /api/desktop/session/bind`);
  привязка «сессия → этап» хранится в `stage_bindings` конфига модуля. Решения
  уходят пачками (`POST /api/desktop/decisions`, ключ установки), ref =
  `<device_id[:8]>-<id инцидента>`, повтор обновляет запись. Нет связи или
  этапа — ждут в базе. Демо-данные на сайт не идут.
- **На сайте** (`ichamps`): модель `LiveDecision` (миграция `b3d9e1f04a62`),
  `blueprints/desktop_live.py` — привязка и приём; автопривязка только при
  совпадении трассы или лиги и единственном лучшем этапе в окне −10/+3 ч, среди
  мероприятий, где пользователь маршал или организатор; номер сессии пишется в
  `StagePlan.linked_subsession_id` (импорт результатов потом сам находит этап).
  Разбор гонки (`stewarding_race.html`) показывает решения по
  `Race.subsession_id`; отложенные закрываются `POST /stewarding/live/<id>/resolve`,
  завершить проверку с открытыми нельзя.
- **Интерфейс:** вкладка главного окна и отдельное окно `/racecontrol` —
  один код `web/ui/rc.js` (лента с фильтрами, панель решения, клавиши
  Z/X/C, Q/W/E/R, Space, ↑↓, Y, L).
- **Окно поверх сима** (`overlay.py`, Tk в главном процессе): плоские
  клавиши `Key`, лента из 7 строк, панель решения, флаги; показ —
  `overlay_hotkeys`. Окно не забирает фокус (`WS_EX_NOACTIVATE`), поэтому
  клавиш решения в нём нет — только мышь. Шрифты Exo 2 / Roboto Mono
  подключаются процессу из `web/ui/fonts` (`AddFontResourceEx`, `FR_PRIVATE`).
- Хранение: инциденты и append-only журнал событий в `irc.sqlite3`.

## 8б. Оверлеи пилота (`modules/pilot`)

Окна поверх сима на машине пилота: standings, relative, radar, wind, engine, setups.
Модуль регистрируется из бандла (`_register_bundled`), по умолчанию выключен.

- **Данные** — `GET /api/pilot/data?id=<окно>`: готовая к отрисовке модель
  и `visible` (окно включено и `IsOnTrack`, не повтор). Только 127.0.0.1.
- **Источники.** Отвод сима 60 Гц: `CarLeftRight`, `CarIdx*` (LapDistPct,
  TrackSurface, EstTime, SessionFlags), `WaterTemp`, `OilTemp`, `OilPress`,
  `EngineWarnings`, `WindVel`, `WindDir`, `YawNorth`, `SessionTimeRemain`.
  Поле — `sim.timing()` в своём потоке раз в 0,25 с: `GapClock` (отрывы),
  `PitTracker`, `SectorTimer` из модуля трансляции. Лицензия и оценка круга
  класса — новые поля `Driver.lic`, `lic_color`, `est_lap`.
- **Фон окон пилота** — `cfg.bg` (%), `PilotPainter.bg`: альфа всей панели (`panel`, с тенью и кромкой),
  подложки полос радара и пустой части дуг «полукругов»; текст не меняется. Кромка таблиц —
  `panel(edge=…)`, жёлтая при `flag_tone == "yellow"` (полный жёлтый, `FlagWatch`).
- **Флаг для волны** (башня, лента событий, Standings/Relative) — `course_flag`: полный жёлтый только по
  `FLAG_CAUTION`/`CAUTION_WAVING` (местный жёлтый участка `FLAG_YELLOW` — нет: в гонке флаги со стороны своей
  машины, отставшему он давал ложные «жёлтый» и «рестарт»); `FlagWatch` засчитывает флаг, продержавшийся 0,5 с,
  зелёный — только рестарт после полного жёлтого или первый старт сессии.
- **Волна флага** — `FlagWatch` из трансляции в модуле пилота (только LIVE), `flag_event {id, tone, age}`
  в данных Standings/Relative при `cfg.flag_wave`; рисует `PilotPainter._flag_wave` поверх кадра (в ключ
  кэша таблицы не входит), тайминги как `ov_paint.wave`: волна 1,1 с, вспышка строки 0,55 с.
- **Пейс-кар в Relative** — `sim.pace_car_idx()` (машина с `CarIsPaceCar` в DriverInfo, в поле не
  входит); строка, пока `CarIdxTrackSurface` 2–3 (пит-лейн, трасса), секунды — по доле круга
  × время своего круга. Показывается всегда, без настройки.
- **Шапка таблиц** — `PilotModule._head()` общая для Standings и Relative (`head` в данных Relative):
  сессия, трасса, SOF, `track_temp`/`air_temp`, инциденты, круг, остаток. У Relative под шапкой —
  температуры значками (`_icon`) и инциденты, под пилотами — круг и время до конца (плитка «подвала»,
  едет вниз со строкой «Говорит»); не влезает — сначала уходит воздух, потом трасса.
- **Relative** — по `CarIdxEstTime` относительно своей машины, свёрнутому в
  ±половину круга (лучший круг или `CarClassEstLapTime`).
- **Радар** — `RadarSides`: сторону и число машин даёт `CarLeftRight`, положение
  по длине — `CarIdxLapDistPct` × длина трассы; рядом — машины на трассе с
  |dm| < длины своей машины (`radar.car_cm`). Одна сторона — все с неё; обе —
  новая машина получает сторону, где сим прибавил машину, и держит её до выхода.
  Перекрывают друг друга по длине — бок о бок (`lane`), иначе друг за другом.
- **Пороги температур** — `TEMP_LIMITS` по `CarPath`: (жёлтый, красный) для воды и масла, как у цифр
  в чёрной плашке iRacing; сняты с экрана (цвет цифры + телеметрия, 20 замеров/с). Есть — цвет
  дуги и тревога по ним (`limits` в данных окна, `_lim_col`), риска на красном; нет — как ниже.
- **Двигатель** — своих порогов нет: красное только по `EngineWarnings`
  (0x01 вода, 0x40 масло, 0x04 давление). Номер вспышки растёт при включении
  любой из ламп; окно рисует мигание само по смене номера. Температура
  включения лампы — `learned[<машина>]`, отметка на шкале. `cfg.style`:
  `rings` (`_engine_rings`: цвет температуры от отметки, `_temp_col`;
  оборотов — `sl` из `PlayerCarSL*RPM` / `DriverInfo.DriverCarSL*RPM`,
  `DriverCarRedLine`, `_rpm_col`; плитки дуг по заполнению /200 и цвету
  с шагом 4) или `card` (прежнее окно).
- **Сетапы** — `modules/pilot/setups.py`, `SetupLog`. Сетап — отпечаток настроек
  `CarSetup` (`setup_hash`, sha1) без замеров с пит-стопа и следствий топлива (`NOT_SETUP`: `LastHotPressure`,
  `LastTemps*`, `TreadRemaining`, `CornerWeight`, `RideHeight`, `FuelLevel`, …) — иначе тот же файл после пита
  выглядел новым; пока имя файла «INVALID_LOADTYPE»/пусто — столбец не заводится;
  проверяется в потоке модуля 4 раза в секунду; подпись — `DriverSetupName`,
  «изм. N» при `DriverSetupIsModified`. Свои сектора — `tick()` из отвода 60 Гц
  по `LapDistPct` с интерполяцией пересечения; сектор грязный при `OnPitRoad`,
  росте `PlayerCarMyIncidentCount` или смене сетапа. Круг — сумма трёх чистых
  секторов одного прохода. Сброс — по (трасса, `car_path`) и разметке секторов.
  Сетапы сессии сохраняются в `pilot_setups.json` (`SetupLog.dump/load`, `version` растёт на каждое
  изменение) и поднимаются после перезапуска, если та же трасса и машина и прошло < 4 ч; у сетапа без
  своих кругов лучший/средний/число кругов — из записи телеметрии этой сессии.
  В окне и списке — только проеханные сетапы (хоть один сектор или круг) и текущий: промежуточные
  состояния гаража (щелчки настроек без выезда) не показываются; «изм. N» нумеруются среди оставшихся.
  Выбор столбцов — по времени последнего использования, плюс `cfg.pin`
  (отпечаток); `cls` у ячейки: `p` — лучшее за сессию, `b` — среди показанных.
  Демо — `demo_summary()`. Рисует `PilotPainter.setups` (столбцы 118 px, с резиной 210).
  История и резина — `modules/telemetry/history.py`, `SetupHistory.get(car_path, TrackName, only_dir)`:
  папки сессий телеметрии этой машины и трассы, сетап по `setup_hash` копии `setups/NNN.yaml`; лучший,
  средний, трасса на лучшем, топливо — `laps.jsonl`; резина (L/M/R) — `laps_ibt.jsonl` (износ за круг,
  средняя температура, горячее давление), иначе последний замер в боксе. Окно берёт только папку
  текущей сессии телеметрии (история прошлых заездов в окне убрана 2026-11-08, `cfg.hist` всегда 0); горячее давление текущего сетапа — `CarSetup.Tires.*.LastHotPressure`.
- **Рация** — `RadioTransmitCarIdx` / `RadioIdx` / `FrequencyIdx` из отвода;
  название частоты — `RadioInfo.Radios[].Frequencies[].FrequencyName`. Реплика
  `{id, car, start, end}` держится 1,2 с после конца. В данных Standings и
  Relative — `voice {id, ended, in_rows, num, name, freq}` и `talk` у строки.
  Окно рисует таблицу один раз (кэш по данным без `voice`), анимацию — поверх
  на каждом кадре: колонки говорящего гаснут, волна и динамик, отсвет,
  строка «Говорит» с открытием места (панель — срез одной заготовки, ~2 мс
  на кадр). Время реплики — по первому появлению в данных (опрос 10 Гц).
- **Отрисовка радара** — плашка = длина машины, индикатор = перекрытие корпуса
  (`_indicator`, двухсотые высоты, плитки в кэше), концы скруглены внутрь границ.
  `visible` — только при машинах рядом (или «индикатор всегда»). Каждая сторона
  появляется и гаснет отдельно (`RADAR_FADE`). Запись — `RadarProbe`, `radar-probe/`.
- **Ветер** — опрос 60 Гц, угол доводится сглаживанием (`WIND_TAU`), основа и
  плитки треугольника по целым градусам кэшируются (~0,13 мс на кадр).
  `cfg.style`: `ring` (без панели, `WIND_BANDS`, цвет к новой полосе за
  `WIND_COLOR_TAU`, плитки кольца по цвету с шагом 4) или `card` (прежний).
- **Плитки** — `_tile` в `pilot_paint.py`: таблицы и двигатель собираются из
  готовых кусков (шапка, левая часть строки, ячейка, цифры), рисуется только
  изменившееся; панель с таблицей склеивается один раз на высоту.
- **Настройки** — `GET /api/pilot/state`, `POST /api/pilot/settings`
  `{id, set | reset | forget_learned}`, `POST /api/pilot/visibility`,
  положения — `GET /api/pilot/positions`, `POST /api/pilot/position`.
- **Окна** — тот же хост (`overlay_host.py`), окна «p:<id>», поток
  `PilotFeed`: опрос радара и ветра 60 Гц, двигателя 20 Гц (там же `RPM`), таблиц 10 Гц (скрытые
  окна — 4 Гц, радар — 20 Гц), постоянное соединение на поток;
  картинка — `core/ui/pilot_paint.py` (PIL; фигуры вдвое крупнее и
  уменьшаются, фигуры и текст — на отдельных слоях: ImageDraw на RGBA
  затирает, а не смешивает). Хост раз в 5 с перечитывает список окон — модуль,
  включённый после старта хоста, получает окна без перезапуска.

канала сплиттера). В iRacing — не проверено: приёмка по ТЗ, п. 7.

- **Старые `.ibt`** — `TelemetryModule._clean_ibt` раз в час: файлы из `ibt.json` сессий iRC старше
  `IBT_KEEP_DAYS` (14) удаляются; не разобранный сначала разбирается (`_reprocess` → `laps_ibt.jsonl`). Прочие
  `.ibt` в папке iRacing не трогаются.

- **Закрытие** — при остановке модуля `.ibt` не разбирается (затягивало выход, перезапуск ради обновления
  спотыкался); после запуска `_reprocess_pending` разбирает сессии за 3 дня, у которых `.ibt` новее разбора.
- **Перезапуск ради обновления** (`core/app.py`) — новая копия стартует после `Wait-Process` старого ядра
  (до 60 с), а не через 7 с вслепую.

## 9. RUTP

С 2.33.0 ливреи загружает сам iRC — отдельный агент RUTP со своим значком в
трее больше не нужен. Цикл перенесён из `rutp/agent/worker.py` в
`modules/rutp/` почти без изменений:

- `client.py` — сервер (`https://testedtest.ru/rutp`, на стандартной
  библиотеке, мимо системного прокси): `/enroll` по секрету активации →
  персональный ключ; `/resolve` → какие файлы есть у пилотов; GET файлов.
  Ответ 401 → ключ сбрасывается, на следующем шаге активация заново.
- `__init__.py` — поток `rutp`, шаг раз в 5 с. Участников и контекст сессии
  (`custId, carPath, teamId, carNumberRaw`, `seriesId, leagueId`) отдаёт
  `SimClient.livery_context()` — своего irSDK у модуля нет. В демо-гонке
  контекста нет, ливреи не грузятся.
- Запись: чужие ливреи — в сессии, их пути в `rutp-written.json` (папка
  данных), после сессии и при остановке модуля удаляются; своя — в начале каждой
  сессии (с 2.67.1; файл занят — повтор до 30 с, `SELF_RETRY_S`), затем `reload_texture` своей
  машины; не удаляется. Временный файл — вне папки
  paint (OneDrive перехватывает недописанные).
- Конфиг модуля: `paint_folder`, `api_key`, `device_id`. При первом запуске
  ключ, номер установки и папка переносятся из `%APPDATA%\RUTP\config.json`
  (флаг `migrated`), активироваться заново не нужно.
- **Отдельный агент.** Пока процесс `RUTP.exe` запущен, модуль ничего не
  пишет: два загрузчика в одной папке paint стирают файлы друг друга.
  `POST /api/rutp/legacy` (кнопка во вкладке, только по нажатию) закрывает
  процесс, удаляет `HKCU\...\Run\RUTP` и убирает чужие ливреи по его
  `%APPDATA%\RUTP\written.json`.

API: `GET /api/rutp/status`; `POST /api/rutp/folder {path}`, `pick` (окно
выбора папки в потоке Tk), `paint` (открыть папку), `reload` (перекачать
ливреи сессии), `legacy`.

Проверено: полный цикл против настоящего сервера на двух пилотах (4 файла
записаны и убраны по концу сессии). В живой сессии iRacing — не проверено.

## 10. Допуск по аккаунту irchamps.gg

Программа работает только у пользователя сайта с привязанным iRacing.

### 10.1. Вход через сайт

Паролей на сайте нет — вход только через Discord, — поэтому логин идёт в
браузере по схеме «loopback-редирект + PKCE» (RFC 8252, RFC 7636), как у
настольных клиентов `gh` и подобных.

```
iRC                                          irchamps.gg (браузер)
verifier = случайный секрет, challenge = base64url(sha256(verifier)), state
открывает /desktop/login?port&state&challenge&device_id&device_name&app_version
                                             не вошёл → /login (Discord) → назад сюда
                                             «Войти в iRC как …» → POST
127.0.0.1:<port>/auth/callback?code&state ◄── редирект, код живёт 2 минуты
сверка state
POST /api/desktop/token {code, verifier, device_id} ──► ключ irc_… (один раз)
POST /api/desktop/verify   X-IRC-Key ──►  {allowed, reason, grace_days, user}
                                          401: unknown_key | revoked | no_key
POST /api/desktop/unlink   X-IRC-Key ──►  установка отозвана
```

Защита:

- **state** — возврат принимается только от входа, начатого этой программой;
- **PKCE** — код бесполезен без секрета: перехватившая его программа ключ не
  получит; неверный секрет сжигает код с первой попытки;
- возврат только на `127.0.0.1`, порт 1024–65535, `device_id` должен совпасть;
- после входа через Discord сайт возвращает на сохранённый адрес, только если
  он начинается с `/desktop` и не содержит `//` — без открытого редиректа.

**Запасной способ — код привязки** (нет браузера на машине):
`POST /api/desktop/pair/start` → код `XXXX-XXXX` на 10 минут → человек вводит
его на `/desktop/pair` → `POST /api/desktop/pair/poll` отдаёт ключ один раз.

Сайт (`ichamps/blueprints/desktop_api.py`):

- таблицы `desktop_installs` (ключ — sha256, одна запись на пользователя и
  машину, повторный вход перевыпускает ключ) и `desktop_pairings`
  (`kind`: `login` | `code`; одноразовые коды, ключ хранится до обмена),
  миграция `a7c2e5d19b34`;
- решение `_decision`: аккаунт подтверждён и `iracing_customer_id` задан;
- страницы: `/desktop/login` — вход программы, `/desktop` — установки и отзыв,
  `/desktop/pair` — код; все через сессию сайта (`session['user_id']`);
- возврат после Discord: `after_login_target` в `discord_oauth.py`;
- лимиты: вход 60/час, обмен кода 60/час, старт кода 20/час, опрос и
  проверка 240/час.

Программа: `License.start_login` / `finish_login`, маршрут `GET /auth/callback`
в `core/server.py`, браузер открывается системный (`webbrowser`), после входа
окно панели поднимается снова.

### 10.2. Решение в программе (`core/license.py`)

| Условие | Итог |
|---|---|
| нет ключа | блок: `not_linked` (или `revoked` / `unknown_key`, если ключ отобрал сайт) |
| сайт ответил «нельзя» | блок: `no_iracing`, `not_confirmed` |
| сайт недоступен, последняя удачная проверка < 7 дней | работает |
| то же, > 7 дней | блок: `offline_expired` |
| сим подключён, `user_id` игрока ≠ привязанному | блок: `other_account` |

- Проверка на сайте при старте и раз в час; решение пересчитывается каждые
  20 с (`_license_loop`) — смена аккаунта в симе и истечение запаса
  срабатывают без сети.
- Блок: `registry.stop_all()`, закрываются пульт и окна оверлеев, запуск
  модулей запрещён. Панель работает — через неё подключаются.
- Состояние — `%LOCALAPPDATA%\iRC\license.json` (`device_id`, `key`, `user`,
  `last_ok`, `reason`). Адрес сайта переопределяется `IRC_SITE` (для проверок).

### 10.3. Включение

Допуск включён с 2.23.0: флаг `ENFORCE` в `core/license.py`, для проверок
выключается переменной окружения `IRC_LICENSE=0` (тогда `decide()` всегда
разрешает работу, а привязанный ключ сверяется с сайтом один раз при старте).

Без допуска программа запускается и работает меню, модули стоят, а правая
часть панели лежит под затемнением (`#lock` в `web/index.html`) с карточкой
входа; содержимое под ним `inert`. Кнопка аккаунта в шапке остаётся доступной.

2. Проверить привязку на боевом сайте.
3. Только потом выпускать сборку iRC с допуском — иначе программа не пустит
   никого.

## 11. Автообновление

- Манифест: `https://github.com/motherpython-dev/irc-releases/releases/latest/download/manifest.json`
  (`config.UPDATE_URL`; пустой `update_url` в конфиге подменяется им).

```json
{"version": "2.19.0", "url": ".../irc-2.19.0.zip", "sha256": "…",
 "min_core": "2.16.0", "notes": "…",
 "core": {"version": "2.16.0", "url": ".../download/installer/iRC-setup.exe", "sha256": "…"}}
```

- Проверка — поток `Application._update_loop`: через 20 с после старта и раз
  в `update_check_interval_min` (60) минут.
- `version` новее и `min_core` ≤ ядра → бандл скачивается, сверяется sha256,
  распаковывается (защита от path traversal), `current.json` переключается;
  применится после перезапуска (`state: bundle_ready`).
- `min_core` новее ядра → скачивается установщик (sha256) в
  `%LOCALAPPDATA%\iRC\updates`; кнопка в панели запускает его `/VERYSILENT`
  после выхода программы и открывает её снова (`state: core_ready`).
- Сам порядок обновления живёт в бандле — его можно чинить обновлением.

Выпуск: `python build/publish.py <версия> --notes "…"` (есть `--dry-run`).

Установщик — по постоянному адресу:
`https://github.com/motherpython-dev/irc-releases/releases/download/installer/iRC-setup.exe`
(релиз `installer`, создан с `--latest=false`, рядом `installer.json` с ядром и
sha256). Пересобирается только с `--installer`, когда меняется ядро; без ключа
`publish.py` проверяет, что ядро установщика совпадает с `bootstrap/version.py`,
и иначе останавливается. Зачем: SmartScreen копит репутацию по отпечатку файла —
один и тот же установщик месяцами, а не новый на каждый выпуск. Новый
установщик — один раз отправить в Microsoft (wdsi/filesubmission, Software
developer → Defender SmartScreen, «Incorrect detection»). Сайт
`/desktop/download` ведёт прямо на этот адрес.

Статус в панели: `uptodate` — «Обновлений нет»; 404 на манифест (выпусков
нет) считается тем же; нет связи — `offline`, спокойный текст и повтор по
расписанию.

Состояние: работает. Первый выпуск — v2.20.0 в публичном репозитории
`motherpython-dev/irc-releases` (в нём только выпуски, без исходного кода).
Клиенты 2.18.0+ с ядром 2.16.0 обновляются сами; 2.17.0 и старше — один раз
установщиком.

## 17. Интерфейс (`web/ui`)

Язык «Тайминг»: сетка 8 px, высоты 32 / 40 / 56, строки и шапки панелей 36,
заголовок таблицы 28, без скруглений, рамка 1 px. Шрифты Exo 2 (интерфейс) и
Roboto Mono (цифры) — внутри программы. Цвета — переменные в начале
`irc.css`; образец всех элементов — `/ui/kit.html`.

- **`irc.setHTML(el, html)`** — обновление без пересоздания: сравнивает новую
  разметку с текущей и меняет только отличающиеся узлы, текст и атрибуты;
  `data-key` — перестановка по ключу. Поле в фокусе не трогается. Так
  устранены пропадавшие клики: раньше окна пересобирали содержимое каждую
  секунду, и элемент под курсором успевал смениться между нажатием и
  отпусканием. Проверка — 50 кликов на фоне обновлений, лишних изменений DOM
  0 (кроме живого текста тайминга).
- **`irc.onoff`, `irc.seg`** — «ВКЛ | ВЫКЛ» и выбор; клики — `irc.on(kind, fn)`,
  обработчиков может быть несколько.
- **`irc.keys(map)`** — горячие клавиши; на одну клавишу можно повесить
  несколько обработчиков: срабатывает первый, вернувший не `false`. Пока
  человек печатает в поле, клавиши без Ctrl не срабатывают; зажатая клавиша
  не повторяет команду (кроме стрелок).
- **`irc.post`** показывает отказ уведомлением (`irc.toast`).
- **`irc.ph(kicker, title, stats)`** — шапка панели в две строки (стиль F): мелкая
  оранжевая строка, заголовок, справа значения `[[подпись, значение, цвет?]]`.
  **`irc.plate(номер)`** — плашка номера в цветах ливреи (`/api/plates`, раз в 5 с):
  два цвета Trading Paints градиентом, иначе цвет конструктора iRacing.
  **`irc.pill(текст, цвет)`** — метка статуса. `.p.fit` — панель по высоте
